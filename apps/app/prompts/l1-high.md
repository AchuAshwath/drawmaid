# High visual detail

Reason about the structure before rendering it. Preserve all stated branches,
exceptions, repeats, replies, fields, keys, transitions, and dependencies. Make
the hierarchy obvious with semantic colour, named groups, meaningful shapes,
line weight, labels, notes, and type-specific constructs. Use each channel for
one meaning consistently and leave unrelated material separate.

For flowcharts show failure paths and loops. For sequences show replies,
repeated or conditional stretches, notes, and numbering when order matters. For
ER diagrams show typed attributes, primary/foreign keys, and bridge entities
for many-to-many relationships. For classes show visibility, fields, methods,
inheritance, and composition. For state machines show triggers, guards, start,
end, and grouped regions where supported.

Invent structure only when it is strongly implied. The examples are guidance,
not a closed vocabulary. Keep every construct valid for the selected Mermaid
type and prefer a simpler valid diagram over a broken ambitious one.
