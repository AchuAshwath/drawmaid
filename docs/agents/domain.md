# Domain docs

Before exploring or changing a domain area, read the root `CONTEXT.md` and
the relevant records in `docs/adr/`. Use the glossary in `CONTEXT.md` when
naming modules, interfaces, tests, issues, or architecture proposals.

This repository uses a single root context. `docs/adr/` contains system-wide
decisions; add a new ADR when a durable architectural choice is made. If a
proposal conflicts with an existing ADR, call out the conflict explicitly
instead of silently overriding it.
